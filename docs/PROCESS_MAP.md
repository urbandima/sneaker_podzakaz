# Process Map — СНИКЕРХЭД

Четыре ключевых бизнес-процесса с участниками, шагами и системными событиями.

---

## 1. Заказ + оплата

**Участники:** Клиент → Система → Менеджер

| # | Шаг | Кто | Статус заказа | Системное событие |
|---|-----|-----|---------------|-------------------|
| 1 | Клиент добавляет товары в корзину и оформляет заказ | Клиент | `new` | `order.created` → `order_history` |
| 2 | Система отправляет заказ в МойСклад | Система | `new` | `moysklad_sync_log` запись |
| 3 | Менеджер подтверждает заказ, указывает итоговую цену | Менеджер | `confirmed` | `order_history.status_changed` |
| 4 | Клиент оплачивает (перевод / QR / карта) и прикрепляет чек | Клиент | `awaiting_payment` | `payment_proof` файл сохранён |
| 5 | Менеджер проверяет оплату и подтверждает | Менеджер | `paid` | `order_history.status_changed` |
| 6 | Заказ уходит на закупку / выкуп | Менеджер | `awaiting_buyout` | `buyout_order_link` создаётся |

```
[Клиент] оформляет заказ
    │
    ▼
[Система] создаёт order, пишет в order_history, пушит в МойСклад
    │
    ▼
[Менеджер] подтверждает → статус confirmed
    │
    ▼
[Клиент] оплачивает, загружает чек
    │
    ▼
[Менеджер] верифицирует оплату → статус paid
    │
    ▼
→ Сценарий 2 (Выкуп)
```

## 2. Выкуп товара (Buyout)

**Участники:** Менеджер/Закупщик → Система → Поставщик

| # | Шаг | Кто | Статус выкупа | Статус заказа |
|---|-----|-----|---------------|---------------|
| 1 | Создать выкуп (вручную или через парсер URL) | Менеджер | `draft` | — |
| 2 | Привязать заказы клиентов к выкупу | Менеджер | `draft` | — |
| 3 | Подтвердить оплату на источнике (Poizon / Lamoda / …) | Закупщик | `ordered` | → `bought_at_source` |
| 4 | Получить трек-номер, указать перевозчика | Закупщик | `in_transit` | → `in_transit_from_source` |
| 5 | Товар прибыл на склад | Закупщик | `arrived` | → `arrived_at_warehouse` |
| 6 | Приёмка: создать `PurchaseOrder`, зачислить остатки | Менеджер | `accepted` | → `ready_to_ship` |

```
[Менеджер] создаёт выкуп (draft)
    │
    ▼
[Менеджер] привязывает заказы клиентов (buyout_order_link)
    │
    ▼
[Закупщик] оформляет на источнике → ordered
    │  → BuyoutStatusSyncService обновляет статусы заказов
    ▼
[Закупщик] трек получен → in_transit
    │  → заказы: in_transit_from_source
    ▼
[Склад] товар получен → arrived
    │  → заказы: arrived_at_warehouse
    ▼
[Менеджер] actionAccept → создаёт PurchaseOrder, accepted
    │  → заказы: ready_to_ship
    ▼
→ Сценарий 4 (Приёмка)
```

**Отмена выкупа:** `cancelled` → заказы возвращаются в `awaiting_buyout`

## 3. Передача паспортных данных

**Участники:** Клиент → Система → Менеджер

| # | Шаг | Кто | Событие |
|---|-----|-----|---------|
| 1 | Менеджер запрашивает паспорт (статус → `waiting_passport`) | Менеджер | `order_history.status_changed` |
| 2 | Клиент переходит по ссылке в письме / SMS | Клиент | — |
| 3 | Клиент заполняет форму паспортных данных (ФИО, серия, номер, выдан) | Клиент | `order.passport_*` поля сохранены |
| 4 | Система логирует факт сохранения | Система | `order_history` action `passport_saved` |
| 5 | Менеджер видит заполненный паспорт в карточке заказа | Менеджер | — |
| 6 | Менеджер переводит заказ на следующий шаг доставки | Менеджер | `order_history.status_changed` |

```
[Менеджер] меняет статус → waiting_passport
    │
    ▼
[Система] отправляет письмо/SMS клиенту со ссылкой (token-based URL)
    │
    ▼
[Клиент] заполняет форму /order/{token} — паспортные данные
    │
    ▼
[Система] сохраняет passport_* поля, пишет в order_history
    │
    ▼
[Менеджер] проверяет данные → переходит к доставке
```

**Безопасность:** данные доступны только по одноразовому токену, паспортные поля видны только в admin.

## 4. Приёмка товара (Receiving / PurchaseOrder)

**Участники:** Кладовщик/Менеджер → Система

| # | Шаг | Кто | Событие |
|---|-----|-----|---------|
| 1 | Инициировать приёмку из карточки выкупа (`actionAccept`) | Менеджер | — |
| 2 | Система создаёт `PurchaseOrder` со статусом `received` | Система | `purchase_order` запись |
| 3 | `buyout.receiving_id` ← ID приёмки, `accepted_at` = now | Система | `buyout_history.receiving_created` |
| 4 | `buyout.status` → `accepted` | Система | `buyout_history.status_changed` |
| 5 | Связанные заказы → `ready_to_ship` | Система | `BuyoutStatusSyncService` |
| 6 | Остатки на складе обновляются (qty зачисляется в `purchase_order_item`) | Система | — |
| 7 | Финансы: shipping_cost + fees распределяются равномерно по qty | Система | `purchase_order_item.unit_cost` |

```
[Менеджер] нажимает «Принять» в карточке выкупа (arrived)
    │
    ▼
[Система] создаёт PurchaseOrder (status=received)
    │  распределяет стоимость по единицам
    ▼
[Система] buyout.receiving_id = PO.id
          buyout.status = accepted
          buyout.accepted_at = now()
    │
    ▼
[Система] BuyoutStatusSyncService
          → linked orders: ready_to_ship
    │
    ▼
[Менеджер] видит товар в «Готов к отправке»
    │
    ▼
→ Сценарий 1 продолжается: отгрузка клиенту
```

## Схема взаимосвязей

```
order ──(buyout_order_link)──► buyout ──► purchase_order
  │                               │
  │                               └──► buyout_history
  │
  ├──► order_history
  ├──► moysklad_sync_log
  └──► payment_proof (files)
```

---

## Ключевые таблицы

| Таблица | Назначение |
|---------|-----------|
| `order` | Заказ клиента |
| `order_history` | Лог всех изменений заказа |
| `buyout` | Единица закупки товара |
| `buyout_order_link` | N:N связь выкуп ↔ заказ |
| `buyout_history` | Лог изменений выкупа |
| `purchase_order` | Приёмка товара на склад |
| `moysklad_sync_log` | Лог попыток синхронизации с МойСклад |
