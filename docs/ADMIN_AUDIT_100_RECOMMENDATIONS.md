# РАЗДЕЛ 1: АРХИТЕКТУРА И СТРУКТУРА (1-15)

## 1.1 Модульность и связи

### 1. Централизовать Event Bus
**Проблема**: Разрозненная событийная система между модулями  
**Решение**: Создать `app\backend\modules\common\events\EventBus`  
**Приоритет**: 🔴 Высокий  
**Выгода**: Упрощение интеграции между Order→Loyalty→Notification

### 2. Внедрить Repository Pattern
**Проблема**: Прямые запросы из контроллеров  
**Решение**: Создать репозитории для Order, Product, Customer  
**Приоритет**: 🔴 Высокий  
**Выгода**: Тестируемость, разделение ответственности

### 3. Создать Service Layer
**Проблема**: Бизнес-логика в контроллерах (OrderController 911 строк)  
**Решение**: Вынести в OrderService, CustomerService  
**Приоритет**: 🔴 Высокий  
**Пример**: OrderController.actionCreate() → OrderService.create()

### 4. Внедрить CQRS для отчетов
**Проблема**: Тяжелые аналитические запросы блокируют основную БД  
**Решение**: Создать read-only реплику для аналитики  
**Приоритет**: 🟡 Средний  
**Выгода**: Производительность админ-панели

### 5. Создать Command Bus
**Проблема**: Сложные операции размазаны по коду  
**Решение**: Команды CreateOrder, UpdateStock, ApplyCoupon  
**Приоритет**: 🟡 Средний  
**Выгода**: Простота расширения, логирование

### 6. Внедрить DTO
**Проблема**: Массивы вместо типизированных объектов  
**Решение**: OrderDto, ProductDto, CustomerDto  
**Приоритет**: 🟡 Средний  
**Выгода**: Type safety, валидация

### 7. Создать API Gateway
**Проблема**: Прямой доступ к модулям извне  
**Решение**: Единая точка входа для API  
**Приоритет**: 🟢 Низкий  
**Выгода**: Безопасность, rate limiting

# РАЗДЕЛ 2: БИЗНЕС-ЛОГИКА (16-40)

## 2.1 Заказы (Order)

### 13. State Machine для статусов
**Проблема**: Статусы проверяются хаотично  
**Решение**: Библиотека `winzou/state-machine`  
**Приоритет**: 🔴 Высокий  
**Статусы**: new → paid → processing → shipped → delivered  
**Переходы**: can('pay'), apply('ship')

### 14. Order Aggregate Root
**Проблема**: OrderItem управляется отдельно  
**Решение**: Order::addItem(), Order::removeItem()  
**Приоритет**: 🔴 Высокий  
**Выгода**: Целостность данных

### 15. Order Total Calculator
**Проблема**: Подсчет суммы в нескольких местах  
**Решение**: OrderTotalCalculator Service  
**Приоритет**: 🔴 Высокий  
**Учитывать**: товары, скидки, доставка, налоги

### 16. Inventory Reservation
**Проблема**: Нет резервирования товара при заказе  
**Решение**: reserved_quantity в product_size  
**Приоритет**: 🔴 Высокий  
**Логика**: Оплата → списание, Отмена → возврат

### 17. Order Timeline
**Проблема**: История размазана по таблицам  
**Решение**: Единая таблица order_timeline  
**Приоритет**: 🟡 Средний  
**Поля**: order_id, event, data, created_by, created_at

### 18. Split Order на подзаказы
**Проблема**: Сложная логистика для разных складов  
**Решение**: Order::createSubOrder()  
**Приоритет**: 🟡 Средний  
**Сценарий**: Товары из разных стран

### 19. Order Validation Rules
**Проблема**: Валидация в модели — громоздко  
**Решение**: Отдельные классы валидации  
**Приоритет**: 🟡 Средний  
**Пример**: DeliveryAddressValidator, PaymentValidator

### 20. Order Number Generator
**Проблема**: Ручное создание номеров  
**Решение**: Сервис с форматом YYYYMMDD-XXXXX  
**Приоритет**: 🟡 Средний  
**Требования**: Уникальность, читаемость
